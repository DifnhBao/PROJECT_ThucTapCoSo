# T09 — Playlist transaction và concurrency

Ngày27/10/2026. Trạng thái: **VERIFIED trên môi trường test local**.

Add/remove/delete playlist đã dùng managed transaction và khóa parent trước khi
đọc/ghi memberships. Add kiểm tra public song bằng shared locking read; duplicate
và max position đọc trong cùng transaction. Giữ409 PLAYLIST_SONG_EXISTS cho duplicate,
có guard INT overflow và retry hữu hạn cho MySQL deadlock/lock timeout. Xóa joins+
parent atomic, không để playlist rỗng do lỗi xóa parent giữa chừng.

Policy và giới hạn: [PLAYLIST_CONCURRENCY_VI.md](../PLAYLIST_CONCURRENCY_VI.md).
Không có reorder hiện hữu, không thêm route mới. Không migration/index/dependency
mới; dùng constraints đã kiểm chứng trong T04. OpenAPI cập nhật mô tả các mutations.
